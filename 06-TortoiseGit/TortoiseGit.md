# TortoiseGit 使用笔记

TortoiseGit 是 Windows 上的 Git 图形化客户端，集成到资源管理器右键菜单中，
适合不习惯命令行的场景，底层仍然调用 Git。

## 前置条件

- 已安装 **Git for Windows**（TortoiseGit 依赖系统中的 Git）。
- 建议同时安装 **中文语言包**（LanguagePack），安装后在设置里选择语言。

## 常用操作（右键菜单）

| 操作 | 说明 |
| ---- | ---- |
| Git Clone | 克隆远程仓库到本地 |
| Git Commit | 提交暂存区更改到本地仓库 |
| Git Pull | 拉取远程最新提交并合并 |
| Git Push | 推送本地提交到远程 |
| Git Sync | 一站式拉取 + 推送 |
| Git Fetch | 只下载远程更新，不合并 |
| Git Log / Show Log | 查看提交历史 |
| Git Create Branch Here | 创建分支 |
| Switch/Checkout | 切换分支 |
| TortoiseGit → Diff | 对比工作区与版本库差异 |
| TortoiseGit → Revert | 撤销本地修改 |

## 提交规范

- 提交前先确认“暂存（Stage）”的文件是否正确，避免误提交无关文件。
- 提交信息写清楚“为什么改”，而不只是“改了什么”。
- 提交后若未推送，本地仓库才会记录，`Push` 后其他人才可见。

## SSH 密钥配置

TortoiseGit 默认使用 PuTTY 风格的密钥（`.ppk`），与 Git Bash 的 OpenSSH 密钥不同：

1. 用 **PuTTYgen** 生成或导入密钥。
2. 使用 **Pageant** 加载私钥（开机启动更省事）。
3. 在 `Settings → Git → Remote` 中把远程地址设为 SSH 形式（`git@github.com:...`）。

> 若已用 `ssh-keygen` 生成过 OpenSSH 密钥，可在 PuTTYgen 中导入 `.ssh/id_ed25519` 再另存为 `.ppk`。

## 与命令行配合

- TortoiseGit 只是图形界面，遇到复杂操作（如 rebase、cherry-pick）仍可回到命令行。
- 右键菜单中的 **Git Bash Here** 可直接在当前目录打开命令行。

## 常见问题

- **换了电脑/账号后提交失败**：检查 Pageant 是否加载了正确私钥，远程地址是否正确。
- **文件状态图标不显示**：资源管理器图标覆盖数量被系统限制，可卸载其他同步软件或调整注册表顺序。
- **提交时提示找不到 git.exe**：在 `Settings → General → Git.exe Path` 中指定 Git 安装路径。

## Git Log 右键菜单常用功能

在 **Git Log / Show Log** 界面右键某个提交，常用功能如下：

### 重置 master 到此版本（Reset）

将当前分支指针（HEAD / master）移动到选中的历史版本。假设历史为 `V1 → V2 → V3`，把 master 重置回 `V2`：

| 模式 | 回到 V2 后，V3 引入的修改如何处理 | 推荐程度 |
| ---- | -------------------------------- | -------- |
| **Soft（软重置）** | 保留 V3 的代码修改，并放在暂存区（Stage）。适合想“回到 V2 但继续修改、重新提交”的场景。 | 推荐了解 |
| **Mixed（混合重置）** | 保留 V3 的代码修改，但取消暂存，放在工作区。适合重新整理要提交的内容。 | 推荐了解 |
| **Hard（硬重置）** | 丢弃 V3 引入的代码修改，同时丢弃其他未提交的修改，工作区彻底回到 V2 状态。 | 谨慎使用 |

> **注意**：Hard 会永久丢失未提交的修改，执行前务必确认工作区无重要未提交内容。

### 还原此版本做出的变更（Revert）

新增一个反向提交，撤销指定版本引入的代码变化，**不删除历史**。

以 `V1 → V2 → V3 → V4` 为例，右键 V2 选择 Revert 后：

- V1：保留。
- V2：保留。
- V3：保留。
- V4：新增一个“撤销 V2 修改”的提交。

**特别注意**：Revert 撤销的是 V2 引入的代码变化，不是删除 V2 之后的所有代码。

如果 V3 修改的代码依赖 V2 新增的功能，撤销 V2 可能导致 V3 的部分功能无法正常工作，需检查冲突。

| 对比项 | Revert | Reset |
| ------ | ------ | ----- |
| 历史记录 | 保留历史，新增撤销记录 | 移动版本指针，可能丢弃后续提交历史 |
| 是否删除后续版本 | 否 | 可能（Hard 模式下会丢弃） |
| 风险 | 较低，适合已推送的分支 | 较高，慎用于已推送的分支 |
